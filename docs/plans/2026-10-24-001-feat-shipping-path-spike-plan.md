# feat: Prove the Cartwheel shipping path (native + cart + romdev)

## Overview

Build one small belt-scroll encounter scene in C against Cartwheel v0.15.1 and prove that a single source tree produces a native macOS arm64 binary and a wasmcart `.wasc` cart, that the cart loads and is drivable through romdev and a browser, and that cross-host gates agree. The spike exits with measured numbers and a pinned version tuple, not with gameplay. Timebox: four working days. At the end of day four the spike stops and reports state, measured numbers, and blockers regardless of completion.

## Problem Frame

Neon Rebellion's stack rests on assumptions nobody on this repo has executed: that Cartwheel/three.c serves a sprite-heavy 2.5D beat 'em up, that carts build from this Mac, and that romdev is a workable agent play loop. Each is cheap to test now and expensive to reverse after assets and gameplay exist. The repo is currently a seed archive (`.gitignore` only); `.context/` is the owner's untracked braindump and stays that way. The first slice needs roughly 40 simultaneous actors (two players, two crowd waves, projectiles) at 60 Hz; that is the budget the spike must meet natively.

Founding decisions already made: C gameplay; belt-scroll melee first; three.c 3D environments with sprite actors; first slice is solo + local 2P; MIT code / CC-BY-4.0 art.

## Requirements Trace

- R1. One C source tree builds, on this Mac, to a native macOS arm64 binary and a `.wasc` cart.
- R2. The cart loads in romdev (local MCP) and runs under deterministic stepping with scripted two-player input, frame stepping, screenshots, and named debug state.
- R3. The same cart runs in Chromium via the engine's runner.
- R4. The scene renders y-ordered sprite actors as three.c planes on a 3D ground plane with simulated jump height, HUD text, one sound, and one environment element (e.g. a lit wall or pillar) with a distinct material from the ground and actors.
- R5. Zero missing three.c shader states (cumulative `cw.three.missing` count, with `cw_app_desc.debug` enabled) on the cart across the full scene run.
- R6. Native frame time at 40 actors meets the budget: p99 ≤ 16.6 ms (60 Hz) with vsync off, measured over a predeclared bounded duration after warm-up; romdev and Chromium numbers (p50/p99/max, memory snapshots, host/readback overhead) are recorded as evidence, not gated.
- R7. Cross-host gates (native vs cart vs browser) compare a whitelisted simulation-state field set plus a per-tick simulation checksum exactly, and frames within declared image tolerances; every gate has a control that fails its own predicate.
- R8. Engine, three.c, wasmcart, wasi-sdk, romdev, and host tool versions pinned in a lockfile and recorded as an ADR.
- R9. Repo is reviewable in Git: LICENSE, art licence, README stub, AGENTS.md, `docs/` structure; `.context/` stays ignored.

## Scope Boundaries

- No combat rules, enemy AI, progression, menus, or audio design.
- No online play, no console targets, no Firefox/Safari.

## Context & Research

### Relevant Code and Patterns

- Out-of-tree project layout from `monteslu/cartwheel-examples@8b6d18d`: `scripts/deps.lock` pins the engine; root `CMakeLists.txt` with `find_package(cartwheel CONFIG)` and `cw_add_app(... SOURCES ... PACK assets/roots.txt)`; app variants via extra `cw_add_app` with compile definitions (`pugball_auto` autopilot pattern).
- Engine tooling at `monteslu/cartwheel-engine@v0.15.1`: `tools/run-cart.mjs --host native|chromium|romdev --frames N --input <script> --state <out>` and `tests/gate.mjs` honor `CW_PROJECT_ROOT` for out-of-tree projects; `tools/programs.mjs <app> --gates` does **not** honor `CW_PROJECT_ROOT` in its gate-survey branch (it reads the engine's build dir and `tests/gates.json`), so the survey must be run explicitly against NR's build and its logs fed to program generation. It emits a manifest (`programs/<app>.txt`) plus generated C tables (`<app>_gl.c`, `<app>_wgpu.c`) that are all committed. Missing states are reported as `cw.three.missing` (count) and `cw.three.missing_states` (text); pipeline reporting requires `cw_app_desc.debug`. `run-cart.mjs` imports Playwright from the engine checkout's `deps/wasmcart` and defaults native audio to a dummy driver; runners default to Linux GPU sandboxing/PCI discovery guards (Darwin launch settings must be validated).
- Engine layout rule: game code targets `include/cartwheel/*.h` only; `src/platform/` is the sole SDL/wasmcart boundary, which is what makes one tree serve both targets.
- Donor sample for systems: engine `games/action2d` (sprites, projectiles, lighting, audio, deterministic replay).
- Panthea conventions to mirror: `docs/decisions/NNNN-slug.md` ADRs with dated amendments (ADR-0001 records exact pins), `docs/evidence/<topic>/README.md` + PNGs, `docs/README.md` authority order, root MIT `LICENSE` with `LICENSES/<other>.txt` for differently licensed subtrees.

## Key Technical Decisions

- **Out-of-tree project, prebuilt SDKs, engine pinned by `scripts/deps.lock`**: no engine fork; upgrades are a lock change with gate reruns.
- **Darwin-local cart toolchain is the primary path**: wasi-sdk 33.0 `arm64-macos` on this host, based on the owner's report that the engine author ships carts from a Mac; unproven upstream (the examples' fetch script adds cart SDKs only on linux-x64). A Darwin-built `.wasc` is an exit criterion. If the arm64-macos wasi-sdk cannot link the cart SDK's ThinLTO bitcode, Unit 4 halts, records the exact error in the ADR, and the owner decides between a `linux/amd64` container as the supported path, asking upstream, or a different SDK.
- **Sprites are alpha-tested textured planes in the three.c scene; depth derived from ground-y with actor-id tiebreak**: one renderer, consistent lighting, exercises the production shader-state path. Nearest filtering and no mips reduce cross-host silhouette variance; the residual is bounded by the calibrated image tolerance.
- **Determinism contract**: fixed tick from `cw_app_desc`; all sim input from the tick snapshot; `cw_rng` and engine deterministic math only; `-ffp-contract=off` on both targets; no wall-clock or audio feedback into sim. Simulation comparison is exact; divergence is investigated or reported as a failed requirement, never absorbed by a tolerance.
- **Cross-host compare policy**: a whitelisted simulation field set (positions, jump heights, rng cursor, actor count, `sfx_tick`, voice-created flag, tick count, input count; raw frame count excluded (romdev runs a frame at load)) plus a rolling per-tick simulation checksum, exact across all hosts; presentation/audio timings and host counters excluded; missing or non-finite values reject. Frames compared to native within declared image tolerances per host pair (stock `gate.mjs` shape); no exact-pixel claim between cart hosts. Sound verified by `sfx_tick` plus successful voice creation plus one audible manual smoke check on native and browser.
- **Shader table is generated before visual acceptance and committed as manifest + C**: SDK builds have no runtime shader builder, so untabled materials are invisible even natively; `programs/spike.txt`, `spike_gl.c`, `spike_wgpu.c` are committed and linked into the spike target. The runtime missing-count gate then runs on the cart over the full scene (jump, HUD, both players, baseline and stress (40) actor counts).
- **External input injection on the ordinary `spike` target**: no `_auto` self-driving variant; cross-host agreement must prove both host input ports, not an internal script.
- **Ordering is asserted geometrically**: depth derives from ground-y via a defined mapping (not `renderOrder`, which does not override depth testing); gates check expected overlap pixels for reversed positions, equal-y actors, and a jumping actor, with an intentionally reversed-mapping control.
- **Evidence policy**: commit screenshots (PNG) and state JSON under `docs/evidence/`; `build/`, `deps/`, `out/`, and `*.wasc` are gitignored. Binaries ship via GitHub Releases later.
- **CMake generator explicit**: Ninja is a declared host requirement (currently missing on this host); preflight fails fast rather than silently falling back to Makefiles.

## Open Questions

### Resolved During Planning

- Three.js→C transpile? No — three.c is a C port of the API; the game is written in C.
- Y-sort in 3D? Cartwheel's y-sort is 2D-only; the spike orders three.c planes by ground-y itself.
- wasmcart 0.34.3 vs romdev `^0.36.1`? Both ABI v4; no documented break. Gate on `wasm{op:conformance}` rather than assume.

### Deferred to Implementation

- Exact three.c state strings for the plane/camera/alpha-test combos: generated from the real draws by `programs.mjs`.
- Baseline actor count and sampling duration: predeclared in Unit 2's evidence README. The stress count (40) and native budget (p99 ≤ 16.6 ms) are fixed by this plan.
- Image tolerance values per host pair: calibrated so a wrong-colour-space frame and a blank frame each independently fail the image predicate while an unrelated tick-counter change does not.
- Bitcode compatibility of `arm64-macos` wasi-sdk with the cart SDK: unverified; Unit 4's cart build answers it.
- Darwin launch settings for the engine runners (GPU sandbox / PCI guards are Linux-oriented): discovered in Unit 2's smoke test; a minimal project-owned adapter is allowed if reuse is blocked.
- Whether `cw_debug_*` values surface through wasmcart's `debugState` without extra plumbing (`WC_FLAG_DEBUG` / `wc_debug_state`).

**Approach:**
- Read `/tool/{name}/schema` for every romdev tool the script calls and fail if the shape differs from the pinned host version.
- Session script: one `x-romdev-session`; `loadMedia` with `deterministicStepMs = 1000/60`; `wasm{conformance}`; `input{sequence}` for two ports; then advance only the remaining frames, accounting for the frame run at load and every frame `input{sequence}` already advanced; assert final tick count before `frame{screenshot}` and `wasm{debugState}`.
- Measurement at the predeclared baseline count and the fixed stress count (40), warm-up excluded, over the predeclared sampling duration: native uncapped (no vsync) frame time p50/p99/max from the engine profiling contract; cart hosts timed externally on GPU-completed frames with host/readback overhead reported as its own column; memory as defined snapshots (native RSS, wasm linear-memory size). Never derive timing from the virtual clock.
- Glyph check: zero `text.glyph_bake` events during the measured interval; prewarm disabled as the control. HUD atlas page count labelled HUD-only; actor texture residency recorded separately.
- Live preview: one `host{op:play, seconds:60}` run observed on `/livestream` and one `playtest{op:open}` window with a real pad, both recorded in the evidence README as the development-loop check.
- Evidence README: tuple, toolchain outcome, gate results, perf table, screenshots per host, cart-host pixel diff summary, atlas/texture numbers, accepted risks.

**Test scenarios:**
- Happy path: native p99 ≤ 16.6 ms at 40 actors.
- Error path: a deliberately added per-actor busy-loop pushes p99 over budget (control).
- Happy path: `host{op:play}` streams the scene and the owner drives player 0 from `playtest`.
- Happy path: session script completes with the expected final tick count, and the saved whitelisted state + checksum equal native for the same input.
- Edge case: no `text.glyph_bake` events in the measured interval; with prewarm disabled, events appear (control).
- Edge case: HUD atlas page count unchanged after warm-up during the stress count.
- Error path: missing session header → documented error, not a silent fresh session.
- Error path: skipping the load-frame adjustment → final tick mismatch is detected before comparison.

**Verification:** Evidence README has every number and a PNG per host; native budget met or the miss is reported as a failed requirement; ADR-0001 final.

## System-Wide Impact

- **Interaction graph:** the engine's `run-cart.mjs`, `gate.mjs`, `programs.mjs` drive everything; the only project-owned glue is `scripts/*` and the romdev session script.
- **Error propagation:** preflight and fetch fail fast with named causes; gates fail with the control that proves them.
- **State lifecycle risks:** stale artifacts across hosts — key every run on tuple + source + asset hash; atlas pages never shrink.
- **Unchanged invariants:** no engine fork; `.context/` untracked; licence split fixed from Unit 1.

## Risks & Dependencies

| Risk | Mitigation |
|------|------------|
| Darwin wasi-sdk cannot link cart SDK ThinLTO bitcode | Spike halts at Unit 4 with the error recorded; owner decision point (container as supported path / upstream / other SDK). Premise 'carts build from this Mac' is then answered no. |
| Missing shader states appear only on cart | Runtime gate on cart over full-scene input, with row-removal control |
| FMA contraction diverges native vs wasm sim | `-ffp-contract=off` both targets; remaining divergence investigated via engine deterministic math/RNG conventions or reported as a failed requirement — never absorbed by tolerance |
| Engine runners assume Linux GPU sandbox / PCI guards | Unit 2 smoke-tests all runners on Darwin before game code; minimal project-owned adapter allowed |
| `programs.mjs` survey ignores `CW_PROJECT_ROOT` | Survey run explicitly against NR's build dir; logs fed to generation; tables committed |
| Colour-space mismatch between hosts | State-exact gating; frame tolerance calibrated with wrong-colour-space control |
| Glyph bake / atlas growth hitches | Prewarm all HUD strings; atlas page count in debug state |
| romdev 0.150.2 vs upstream 0.151.1 schema drift | Pin observed host version; Unit 6's session script reads `/tool/{name}/schema` live rather than trusting the skill text |
| Version churn (engine, examples, romdev all differ) | Lockfile + ADR; upgrades are deliberate tasks with gate reruns |
| Emulated container builds slow or OOM | Only relevant if the owner selects the container path after Unit 4; record build time and memory setting in the ADR. |
